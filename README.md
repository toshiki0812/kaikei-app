# 夫婦家計管理アプリ

夫婦の収入・支出・投資を月次で記録し、10年間（120ヶ月）のキャッシュフローと投資残高をシミュレーションするWebアプリです。ボーナスなどの臨時収入やイベント出費も見込んで計画できます。

データはクラウドのデータベースに保存するので、**二人がそれぞれのスマホ・PCから、外出先でも同じ家計を見られます。**

---

## 二人で使えるようにする（初回だけ）

全体像は「**Neonでデータベースを作る → コードをGitHubに置く → Streamlit Community Cloudで動かす**」の3ステップです。**クレジットカード登録は一切不要**、すべて無料でできます。

### ステップ1: Neon（データベース）を作る

データベースは [Neon](https://neon.tech)（PostgreSQLのマネージドサービス）を使います。無料枠があり、クレジットカード登録も不要です。

1. [neon.tech](https://neon.tech) でアカウントを作り、新しいプロジェクトを作成します（リージョンは東京に近い `AWS Asia Pacific (Tokyo)` などを選ぶと表示が速くなります）
2. プロジェクト作成後の画面（またはNeonダッシュボードの「Connect」）に表示される **接続文字列（Connection string）** を控えます。`postgresql://ユーザー:パスワード@ホスト/データベース名?sslmode=require` の形式です

> Neonは使っていない時間は自動でスリープするため、無料枠でも常時起動のデータベースよりコストを抑えられます。スリープからの復帰で最初の読み込みが少し遅くなることがありますが、実用上は問題ありません。

### ステップ2: コードをGitHubに置く

1. GitHubで**新しいリポジトリを作成**します。Private（非公開）で構いません（Streamlit Community Cloudは無料でもPrivateリポジトリをデプロイできます）
2. このフォルダの中身をそのリポジトリにアップロードします

> **重要**: 同梱の `.gitignore` により、家計データ（`data/`）・接続情報（`.streamlit/secrets.toml`）・このフォルダ内の別プロジェクト（`kabu_log/` `chika_map/`）はアップロードされません。アップロード後、リポジトリ内にこれらが無いことを一度確認すると安心です。

### ステップ3: Streamlit Community Cloud にデプロイする

1. [share.streamlit.io](https://share.streamlit.io) を開き、GitHubアカウントでサインインします
2. 「New app」→ ステップ2で作ったリポジトリ・ブランチ・メインファイル（`app.py`）を選びます
3. 「Advanced settings」の「Secrets」欄に、`.streamlit/secrets.toml` と同じ内容を貼り付けます
   ```toml
   database_url = "ステップ1で控えたNeonの接続文字列"
   app_password = "二人で共有する合言葉（推測されにくい長めのもの）"
   ```
4. 「Deploy」を押します。数分でビルドが終わり、`https://xxxxx.streamlit.app` のようなURLが発行されます

デプロイ後に接続文字列や合言葉を変えたくなったら、アプリ管理画面の「⋮ → Settings → Secrets」からいつでも書き換えられます（保存すると自動で再起動します）。

> アクセスをさらに絞りたい場合は、同じ管理画面の「Settings → Sharing」で「Who can view this app」を編集し、招待した人（夫婦それぞれのメールアドレス）だけに限定できます。

### すでにローカルで入力していた場合

クラウドに切り替える前にデータを入力していたなら、下記で移せます（何も入力していなければ不要です）。

```bash
cd このフォルダ
export DATABASE_URL="Neonの接続文字列"
./venv/bin/python scripts/import_from_sqlite.py data/kakei.db
```

Postgres側に既にデータが入っているテーブルは自動でスキップされるので、誤って上書き・重複することはありません。

## 自分のMacから使う場合

クラウドと同じデータベース（Neon）を見に行くので、スマホから入力した内容もそのまま反映されます。インターネット経由でそのまま繋がるので、プロキシなどの追加設定は不要です。

1. `.streamlit/secrets.toml.example` を複製して `.streamlit/secrets.toml` を作り、次のように記入します
   ```toml
   database_url = "Neonの接続文字列"
   app_password = "クラウド版と同じ合言葉"
   ```
2. `run.command` をダブルクリックします
   - 初回はセキュリティ確認が出ることがあります。その場合は右クリック→「開く」を選んでください
   - 初回起動時は仮想環境の作成とライブラリのインストールが走るため数分かかります
3. ブラウザが開いたら、合言葉を入力して開きます

## プラン（シナリオ）について

「住宅を買う場合／買わない場合」「妻が時短勤務にする場合」のように、**前提の違うシナリオをプランA・プランBとして複数作って比較**できます。

- **プランごとに変わるもの**：収入・クレカ・家賃・投資拠出などの想定額、想定利回り、開始残高、臨時収支（ボーナスや住宅購入など）
- **全プランで共通のもの**：入力した実績（実際の収入・クレカ明細・月末残高）、氏名、カードの登録

実績は「実際に起きた事実」なので、1回入力すればどのプランにも反映されます。プランを増やしても入力の手間は変わりません。

プランは画面左のサイドバーでいつでも切り替えられます。新しいプランは「初期設定」ページの「プラン」タブから作成でき、**既存プランをコピーして作れる**ので、違う部分だけ直せば済みます。

## 画面構成

アプリは4つのページで構成されています。

1. **ホーム** — 表示中プランの今月の収支サマリーと、10年後の見通しを一目で確認できます。
2. **初期設定** — シミュレーションの前提をすべてここで登録します。5つのタブに分かれています。
   - *プラン*：プランの作成・コピー・切り替え・改名・削除
   - *毎月の想定*：氏名と、夫婦それぞれの収入・クレカ利用額・家賃・投資拠出・その他の支出（人ごとの表で入力）
   - *資産・運用*：想定利回り（デフォルト5%）と複利の頻度、シミュレーション開始月、**人ごとの開始残高**、**人ごとの現金の上限（自動投資振替）**
   - *臨時収支*：ボーナスやイベント出費を**表形式でまとめて追加・編集**。1行ずつ対象者を選びます
   - *カード*：夫婦それぞれのクレジットカードの登録（保有者の指定が必要）
3. **月次実績入力** — 毎月の実際の収入・家賃・投資拠出・現金残高などを、夫婦それぞれの列に入力します。クレジットカード明細は本人のカードのCSVを取り込むと、その人の実績として自動集計されます。空欄のままにした項目は想定値が使われます。**ここで入力する実績は全プラン共通です。**
4. **シミュレーション** — 上部で「世帯合計／夫／妻」を切り替えたうえで、3つの表示を選べます。
   - *グラフ*：現金残高・投資残高・月々の支出内訳。実績が入っている月は実線、未入力の月は想定値にもとづく破線
   - *月別一覧*：120ヶ月分の内訳を表で確認、CSVダウンロード可
   - *プラン比較*：複数プランの現金残高・投資残高を同じグラフに重ね、10年後の数値を並べた比較表を表示

## 「その他（現金支出）」について

収入から家賃・クレジットカード・投資拠出・その他既知の支出を差し引き、さらに銀行口座残高の増減を反映した「残り」を、現金で使った生活費として自動計算しています。この金額を正しく出すには、毎月の**現金残高（銀行口座の月末残高）**の入力が欠かせません。

## 夫婦それぞれで別々にシミュレーション

収入もクレジットカードも家賃も、**すべて人ごとに入力**し、夫・妻それぞれ独立して10年分を試算します。世帯合計は二人分を足して自動計算されるので、シミュレーション画面で「世帯合計／夫／妻」を切り替えて見られます。

家賃などの共通の支出も、**実際にどちらの口座から出ているか**に合わせて1人ずつ入力してください（例：家賃12万円のうち夫が9万円、妻が3万円を負担）。按分率のような設定は持たない代わりに、実際のお金の動きをそのまま表せます。

クレジットカードは、「初期設定」でカードを登録する際に保有者を指定します。「月次実績入力」で本人のカードのCSVを取り込むと、その人の実績としてのみ集計されます。

## 現金がたまったら自動で投資に回す

「初期設定」→「資産・運用」で、人ごとに**現金の上限**を決められます。現金残高がその額を超えた月は、超過分が自動的に投資へ回る前提で試算されます（0にすると自動振替なし）。

実績の現金残高を入力した月には適用されません。実際の残高がそのまま正しい値であり、振替したかどうかは既にその結果に含まれているためです。

## クレジットカード明細のCSV取込について

銀行・カードのオンライン連携（自動同期）は、認証情報や有料の連携サービス契約が必要になるため本アプリには組み込んでいません。代わりに、カード会社のWebサイトから明細をCSVでダウンロードして取り込む方式にしています。

- 楽天カード、三井住友カード、JCBなど主要カードは会員サイトの利用明細ページからCSV/Excel形式でダウンロードできます。
- 文字コードはShift-JIS（cp932）のことが多く、アプリ側で自動判定します（うまくいかない場合は手動選択も可能）。
- 列名はカード会社によって異なるため、取込時に「日付・内容・金額」の列を画面上で指定できます。
- 同じファイルを再度取り込んでも、同一取引は重複登録されません。

## 臨時収支（ボーナス・イベント出費）について

家賃やクレカのような毎月一定の想定値とは別に、「初期設定」ページの「臨時収支」タブで特定の月にだけ発生する収入・支出を登録できます。

- **毎年繰り返し**：ボーナスのように毎年同じ月に発生するものは、「毎年6月に30万円」のように1回登録すれば、10年分すべての該当月に自動反映されます。特定の期間だけに限定したい場合は開始年・終了年も指定できます。
- **単発**：旅行や家電の買い替えなど1回きりの支出・収入は、発生する年月を指定して登録します。

登録した内容は、ダッシュボードや月別一覧のシミュレーションにその月だけ上乗せされます。

## データの保存場所とバックアップ

すべてのデータはクラウドのPostgreSQL（Neon）に保存されます。二人がどこから開いても同じデータを見ます。

Neonは無料プランでも直近の状態から**最大24時間前まで**さかのぼれる仕組み（Point-in-time restore／Instant restore）を備えています。Neonダッシュボードの該当プロジェクト → 「Restore」から復元できます。念のため手元にも控えたい場合は、`pg_dump` で書き出せます。

```bash
pg_dump "Neonの接続文字列" > kakei_backup_$(date +%Y%m%d).sql
```

## 気をつけていただきたいこと

- **合言葉と接続文字列は、この2つが漏れると家計の中身が見られます。** チャットやメールで送らず、パスワード管理アプリなどで共有してください
- **GitHubのリポジトリは必ず Private に**してください
- `.streamlit/secrets.toml` と `data/` は `.gitignore` で除外済みです。この設定は変更しないでください
- Neon・Streamlit Community Cloudとも無料プランの範囲内であれば課金は発生しません。Neonの無料枠には保存容量や稼働時間の上限があるため、家計簿程度の用途なら十分ですが、心配なときは各サービスのダッシュボードで使用量を確認してください

## 今後の変更について

デザインや機能を変えても、入力済みのデータはそのまま残ります。データはコードとは別のデータベースにあるためです。項目が増えるような変更のときも、既存データを引き継ぐ移行処理を用意します。
